先抓住一个最核心的关系：

> `then()` 返回的那个新 Promise，最终是什么状态，完全由回调函数的返回值决定。

你这套实现可以拆成 4 个部分来记：

1. Promise 状态机
2. `resolvePromise`：解析一个值
3. `then`：注册回调并创建下一个 Promise
4. `_flushHandlers`：执行回调并决定下一个 Promise 的状态

---

## 一、先分清代码里的三个 Promise/值

这是手写 Promise 最容易混乱的地方。

假设：

```
const p2 = p1.then((value) => {
  return x;
});
```

这里有三个角色：

- `p1`：当前 Promise，也就是调用 `.then()` 的 Promise
- `p2`：`then()` 返回的新 Promise
- `x`：回调函数的返回值，用来决定 `p2` 的状态

关系是：

```
p1 状态确定
   ↓
执行 then 回调
   ↓
得到返回值 x
   ↓
resolvePromise(p2, x)
   ↓
用 x 决定 p2 的状态
```

因此你代码中的：

```
resolvePromise(promise, x);
```

可以理解成：

```
请使用 x，解析并决定 promise 的最终状态。
```

---

# 二、Promise 的状态机

```
const FULFILLED = "fulfilled";
const REJECTED = "rejected";
const PENDING = "pending";
```

Promise 只有三种状态：

```
pending ─────→ fulfilled
    │
    └────────→ rejected
```

一旦从 `pending` 变成了 `fulfilled` 或 `rejected`，就不能再改变。

所以 `resolvePromise` 和 `rejectPromise` 开头都有：

```
if (promise._state !== PENDING) return;
```

它保证：

```
const p = new MyPromise((resolve, reject) => {
  resolve(1);
  reject("error");
  resolve(2);
});
```

只有第一次有效。

最终理论上应该是：

```
fulfilled 1
```

不过你当前代码在“resolve 一个仍然 pending 的 Promise/thenable”时还存在一个边界问题，后面会说。

---

# 三、辅助判断：什么是 thenable

```
const isObject = (val) => typeof val === "object" && val !== null;
const isFunction = (val) => typeof val === "function";

const isthenable = (val) =>
  (isObject(val) || isFunction(val)) && isFunction(val.then);
```

thenable 就是一个拥有 `.then()` 方法的对象或函数。

例如：

```
const x = {
  then(resolve, reject) {
    resolve(100);
  },
};
```

它虽然不是 `MyPromise` 实例，但它有 `.then()`，所以 Promise 应该把它当成 Promise 一样吸收。

原生 Promise 也是 thenable：

```
const x = Promise.resolve(1);
```

你的 `MyPromise` 同样是 thenable，因为它有：

```
then(onFulfilled, onRejected) {}
```

# 四、constructor 的执行流程

```
constructor(executor) {
  const resolve = (data) => {
    resolvePromise(this, data);
  };

  const reject = (error) => {
    rejectPromise(this, error);
  };

  try {
    executor(resolve, reject);
  } catch (error) {
    reject(error);
  }
}
```

调用：

```
new MyPromise((resolve, reject) => {
  resolve(1);
});
```

流程如下：

```
创建 MyPromise 实例
       ↓
字段初始化
_state = pending
_data = undefined
_reason = undefined
_settledHandles = []
       ↓
创建 resolve 和 reject
       ↓
同步执行 executor(resolve, reject)
       ↓
executor 调用 resolve(1)
       ↓
resolvePromise(当前 Promise, 1)
```

注意：`executor` 是同步执行的。

例如：

```
console.log(1);

new MyPromise(() => {
  console.log(2);
});

console.log(3);
```

输出：

```
1
2
3
```

`try...catch` 用来捕获 executor 中的同步异常：

```
const p = new MyPromise(() => {
  throw new Error("出错了");
});
```

相当于：

```
const p = new MyPromise((resolve, reject) => {
  reject(new Error("出错了"));
});
```

# 五、resolvePromise 是整个实现的核心

```
const resolvePromise = (promise, x) => {
  if (promise._state !== PENDING) return;

  if (isthenable(x)) {
    if (x === promise) {
      rejectPromise(
        promise,
        new TypeError("Chaining cycle detected for promise #<Promise>"),
      );
    }

    queueMicrotask(() => {
      x.then(
        (data) => resolvePromise(promise, data),
        (error) => rejectPromise(promise, error),
      );
    });
  } else {
    promise._state = FULFILLED;
    promise._data = x;
    _flushHandlers(promise);
  }
};
```

它需要分两大类处理。

## 情况一：x 是普通值

例如：

```
resolvePromise(promise, 1);
```

由于 `1` 不是 thenable，所以直接让目标 Promise 成功：

```
promise._state = FULFILLED;
promise._data = 1;
_flushHandlers(promise);
```

流程：

```
resolvePromise(promise, 1)
       ↓
1 不是 thenable
       ↓
promise 变成 fulfilled
       ↓
promise._data = 1
       ↓
执行之前注册的 then 回调
```

字符串、布尔值、`null`、`undefined`、没有 `.then()` 的普通对象，都是直接成功。

---

## 情况二：x 是 Promise/thenable

例如：

```
resolvePromise(p3, p2);
```

此时不能简单写：

```
p3._state = FULFILLED;
p3._data = p2;
```

因为 Promise 的规则是“吸收状态”。

如果：

```
p2 最终 fulfilled，值是 1
```

那么：

```
p3 最终也应该 fulfilled，值是 1
```

而不是：

```
p3 fulfilled，值是 p2 对象
```

所以代码调用：

```
x.then(
  (data) => resolvePromise(promise, data),
  (error) => rejectPromise(promise, error),
);
```

翻译成中文就是：

```
等待 x 的结果：

如果 x 成功：
    继续拿 x 的成功值解析目标 promise

如果 x 失败：
    让目标 promise 也失败
```

为什么成功后还要递归调用 `resolvePromise`？

因为 `data` 可能又是一个 Promise：

```
p1 resolve p2
p2 resolve p3
p3 resolve 100
```

最终必须一层层拆开：

```
p1
 ↓ 吸收
p2
 ↓ 吸收
p3
 ↓ 得到
100
```

最终所有外层 Promise 都应该得到 `100`。

---

# 六、为什么要判断循环引用

```
if (x === promise) {
  rejectPromise(
    promise,
    new TypeError("Chaining cycle detected for promise #<Promise>"),
  );
}
```

看这个例子：

```
const p1 = new MyPromise((resolve) => {
  resolve(1);
});

const p2 = p1.then(() => {
  return p2;
});
```

这里：

```
p2 的状态由回调返回值决定
回调返回值又是 p2 自己
```

也就是：

```
用 p2 决定 p2
```

形成死循环，所以必须 reject。

你的代码这里需要补一个 `return`：

```
if (x === promise) {
  return rejectPromise(
    promise,
    new TypeError("Chaining cycle detected for promise #<Promise>"),
  );
}
```

否则 reject 后还会继续执行下面的：

```
queueMicrotask(() => {
  x.then(...);
});
```

虽然因为状态已经变成 `rejected`，通常不会再次改变结果，但会产生不必要的操作。

---

# 七、rejectPromise 比较简单

```
const rejectPromise = (promise, reason) => {
  if (promise._state !== PENDING) return;

  promise._state = REJECTED;
  promise._reason = reason;

  _flushHandlers(promise);
};
```

流程就是：

```
Promise 还是 pending 吗？
       ↓ 是
状态变成 rejected
       ↓
保存失败原因 reason
       ↓
执行之前注册的 then 回调
```

成功值放在：

```
promise._data
```

失败原因放在：

```
promise._reason
```

---

# 八、then 的完整流程

```
then(onFulfilled, onRejected) {
  const promise = new MyPromise(() => {});

  this._settledHandles.push({
    onFulfilled,
    onRejected,
    promise,
  });

  _flushHandlers(this);

  return promise;
}
```

假设：

```
const p2 = p1.then(
  (data) => data + 1,
  (reason) => console.log(reason),
);
```

## 第一步：创建一个新 Promise

```
const promise = new MyPromise(() => {});
```

这个新 Promise 就是 `p2`。

为什么必须创建新的 Promise？

因为链式调用中，每一次 `.then()` 都要返回不同的 Promise：

```
const p1 = new MyPromise(...);
const p2 = p1.then(...);
const p3 = p2.then(...);
```

关系是：

```
p1 --then--> p2 --then--> p3
```

一般情况下：

```
p1 !== p2
p2 !== p3
```

---

## 第二步：保存回调

```
this._settledHandles.push({
  onFulfilled,
  onRejected,
  promise,
});
```

这里的 `this` 是当前 Promise，也就是 `p1`。

保存的数据可以理解成：

```
{
  onFulfilled, // p1 成功后执行
  onRejected,  // p1 失败后执行
  promise,     // 回调结果决定这个新 Promise
}
```

为什么需要保存？

因为调用 `then()` 时，当前 Promise 可能还处于 `pending`：

```
const p1 = new MyPromise((resolve) => {
  setTimeout(() => resolve(1), 1000);
});

p1.then((data) => {
  console.log(data);
});
```

调用 `then()` 时还没有结果，所以只能先把回调存起来。等 1 秒后 Promise 状态确定，再执行。

---

## 第三步：尝试执行回调

```
_flushHandlers(this);
```

如果当前 Promise 仍然是 `pending`：

```
if (curPromise._state === PENDING) return;
```

什么都不做，回调继续保存在数组里。

如果已经是 `fulfilled` 或 `rejected`，就安排微任务执行。

---

## 第四步：返回新 Promise

```
return promise;
```

于是可以继续链式调用：

```
p1
  .then((data) => data + 1)
  .then((data) => data + 1)
  .then(console.log);
```

---

# 九、_flushHandlers 如何执行回调

```
const _flushHandlers = (curPromise) => {
  if (curPromise._state === PENDING) return;

  const settledHandlers = curPromise._settledHandles;

  queueMicrotask(() => {
    while (settledHandlers.length) {
      const handler = settledHandlers.shift();
      const { onFulfilled, onRejected, promise } = handler;

      // ...
    }
  });
};
```

首先：

```
if (curPromise._state === PENDING) return;
```

状态还没确定，不能执行回调。

状态确定后，也不是立即执行，而是：

```
queueMicrotask(() => {
  // 执行回调
});
```

这保证 `then` 回调是异步执行的。

例如：

```
const p = new MyPromise((resolve) => {
  resolve(1);
});

p.then(() => {
  console.log(2);
});

console.log(1);
```

输出：

```
1
2
```

# 十、状态穿透

## fulfilled 穿透

```
if (!isFunction(onFulfilled) && curPromise._state === FULFILLED) {
  resolvePromise(promise, curPromise._data);
  continue;
}
```

例如：

```
MyPromise.resolve(1)
  .then()
  .then(console.log);
```

第一个 `.then()` 没有传成功回调。

结果不能丢失，而是应该把 `1` 传给下一个 Promise：

```
当前 Promise fulfilled 1
       ↓
没有 onFulfilled
       ↓
返回的新 Promise 也 fulfilled 1
```

相当于默认回调：

```
onFulfilled = (value) => value;
```

---

## rejected 穿透

```
if (!isFunction(onRejected) && curPromise._state === REJECTED) {
  rejectPromise(promise, curPromise._reason);
  continue;
}
```

例如：

```
p1
  .then((value) => value)
  .then((value) => value)
  .then(undefined, (error) => {
    console.log(error);
  });
```

前面没有错误处理函数，错误应该一直往后传。

相当于默认回调：

```
onRejected = (reason) => {
  throw reason;
};
```

---

# 十一、回调返回值决定新 Promise

核心代码：

```
try {
  const result =
    curPromise._state === FULFILLED
      ? onFulfilled(curPromise._data)
      : onRejected(curPromise._reason);

  resolvePromise(promise, result);
} catch (error) {
  rejectPromise(promise, error);
}
```

这里的：

```
promise
```

是 `then()` 返回的新 Promise。

---

## 情况一：回调返回普通值

```
const p2 = p1.then((data) => {
  return data + 1;
});
```

假设 `p1` 的值是 `1`：

```
const result = onFulfilled(1);
// result === 2

resolvePromise(p2, 2);
```

`2` 是普通值，所以：

```
p2 fulfilled 2
```

---

## 情况二：回调没有 return

```
const p2 = p1.then((data) => {
  console.log(data);
});
```

函数没有返回值，相当于：

```
return undefined;
```

于是：

```
resolvePromise(p2, undefined);
```

最终：

```
p2 fulfilled undefined
```

---

## 情况三：回调返回 Promise

```
const p2 = p1.then(() => {
  return anotherPromise;
});
```

执行：

```
resolvePromise(p2, anotherPromise);
```

`p2` 会吸收 `anotherPromise` 的状态：

```
anotherPromise fulfilled 100
        ↓
p2 fulfilled 100
```

或者：

```
anotherPromise rejected error
        ↓
p2 rejected error
```

---

## 情况四：回调抛出异常

```
const p2 = p1.then(() => {
  throw new Error("失败");
});
```

异常被 `catch` 捕获：

```
catch (error) {
  rejectPromise(p2, error);
}
```

最终：

```
p2 rejected Error("失败")
```

这也是为什么：

```
p1
  .then(() => {
    throw new Error("失败");
  })
  .then(undefined, (error) => {
    console.log(error);
  });
```

后面的错误处理能够接收到异常。

---

# 十二、详细分析你的 p2、p3

代码：

```
const p2 = new MyPromise((resolve) => resolve(1));
const p3 = new MyPromise((resolve, reject) => resolve(p2));

queueMicrotask(() =>
  queueMicrotask(() => console.log(p3))
);
```

## 第一步：创建 p2

```
const p2 = new MyPromise((resolve) => resolve(1));
```

初始化：

```
p2._state = "pending";
p2._data = undefined;
p2._settledHandles = [];
```

然后同步执行 executor：

```
(resolve) => resolve(1)
```

调用：

```
resolvePromise(p2, 1);
```

`1` 不是 thenable，所以：

```
p2._state = FULFILLED;
p2._data = 1;
_flushHandlers(p2);
```

此时：

```
p2 = {
  _state: "fulfilled",
  _data: 1,
  _reason: undefined,
  _settledHandles: [],
};
```

`_flushHandlers(p2)` 会安排一个微任务，记作：

```
微任务 A：清空 p2 的回调
```

但现在 p2 还没有回调，所以 A 执行时基本什么都不做。

---

## 第二步：创建 p3

```
const p3 = new MyPromise((resolve, reject) => resolve(p2));
```

初始化：

```
p3._state = "pending";
p3._data = undefined;
p3._settledHandles = [];
```

同步执行：

```
resolve(p2);
```

也就是：

```
resolvePromise(p3, p2);
```

因为 `p2` 有 `.then()`，所以是 thenable。

并且：

```
p2 !== p3
```

于是安排微任务：

```
queueMicrotask(() => {
  p2.then(
    (data) => resolvePromise(p3, data),
    (error) => rejectPromise(p3, error),
  );
});
```

把它记作：

```
微任务 B：调用 p2.then(...)
```

此时 p3 还没有成功：

```
p3._state === "pending";
```

当前微任务队列大致为：

```
[A, B]
```

---

## 第三步：安排你自己的微任务

```
queueMicrotask(() =>
  queueMicrotask(() => console.log(p3))
);
```

外层微任务记作 C：

```
微任务 C：再安排一个 console 微任务
```

此时队列：

```
[A, B, C]
```

---

## 第四步：执行微任务 A

A 是：

```
清空 p2 回调
```

但是 p2 当前没有回调，所以结束。

队列变成：

```
[B, C]
```

---

## 第五步：执行微任务 B

B 中调用：

```
p2.then(
  (data) => resolvePromise(p3, data),
  (error) => rejectPromise(p3, error),
);
```

进入 `p2.then()`。

### B.1 创建一个额外的新 Promise

```
const promise = new MyPromise(() => {});
```

为了方便，把它叫作 `p4`。

即使这个 `then()` 的返回值没有被你接收，它依然会创建一个 Promise。

### B.2 把回调放进 p2

```
p2._settledHandles.push({
  onFulfilled: (data) => resolvePromise(p3, data),
  onRejected: (error) => rejectPromise(p3, error),
  promise: p4,
});
```

### B.3 调用 `_flushHandlers(p2)`

因为 p2 已经 fulfilled，所以又安排一个微任务，记作 E：

```
微任务 E：执行 p2 的 then 回调
```

B 结束时，队列大致是：

```
[C, E]
```

---

## 第六步：执行微任务 C

C 的内容是：

```
queueMicrotask(() => console.log(p3));
```

所以 C 不会立刻打印，而是再安排一个微任务 D：

```
微任务 D：console.log(p3)
```

队列变成：

```
[E, D]
```

注意顺序：E 在 D 前面。

这正是为什么你嵌套了两层 `queueMicrotask` 后，可以看到 p3 已经成功。

---

## 第七步：执行微任务 E

E 开始处理 p2 的回调。

p2 是成功状态：

```
p2._state === FULFILLED;
p2._data === 1;
```

所以执行：

```
onFulfilled(1);
```

这个 `onFulfilled` 是：

```
(data) => resolvePromise(p3, data)
```

于是变成：

```
resolvePromise(p3, 1);
```

`1` 是普通值，因此：

```
p3._state = FULFILLED;
p3._data = 1;
_flushHandlers(p3);
```

这时 p3 正式变成：

```
{
  _state: "fulfilled",
  _data: 1,
  _reason: undefined,
  _settledHandles: [],
}
```

另外，这个回调：

```
(data) => resolvePromise(p3, data)
```

没有显式返回值，所以它返回 `undefined`。

于是 `_flushHandlers` 还会执行：

```
resolvePromise(p4, undefined);
```

让刚才 `p2.then()` 创建的 `p4` 成功：

```
p4 fulfilled undefined
```

但你没有保存 p4，因此它对最终输出没有影响。

---

## 第八步：执行微任务 D

现在执行：

```
console.log(p3);
```

由于 E 已经先把 p3 修改成成功状态，所以理论上看到：

```
MyPromise {
  _state: "fulfilled",
  _data: 1,
  _reason: undefined,
  _settledHandles: []
}
```

完整的关键顺序是：

```
同步代码：
创建 p2 → p2 fulfilled 1
创建 p3 → 安排吸收 p2 的微任务

微任务：
A：处理 p2 原来的空回调
B：执行 p2.then()，安排 E
C：安排打印任务 D
E：拿到 p2 的值 1，让 p3 fulfilled 1
D：打印 p3
```

---

# 十三、为什么少嵌套一层可能看到 pending

如果写：

```
queueMicrotask(() => console.log(p3));
```

初始队列大致是：

```
[A, B, 打印 p3]
```

执行 B 时，只是调用 `p2.then()`，又把真正执行回调的任务 E 放到队尾：

```
[打印 p3, E]
```

所以打印任务可能先执行：

```
p3 还是 pending
```

然后 E 才让 p3 成功。

而两层微任务：

```
queueMicrotask(() => {
  queueMicrotask(() => console.log(p3));
});
```

会把真正的打印任务推迟一轮，使它排在 E 后面。

调试时最好打印字段：

```
console.log(p3._state, p3._data);
```

部分浏览器控制台展示对象时可能是“实时展开”的，会让你误以为打印当时就已经改变了状态。

# 十四、自己手写时建议按照这个顺序

## 1. 写状态和实例字段

```
const PENDING = "pending";
const FULFILLED = "fulfilled";
const REJECTED = "rejected";

class MyPromise {
  _state = PENDING;
  _data = undefined;
  _reason = undefined;
  _settledHandles = [];
}
```

## 2. 写 reject

reject 最简单：

```
如果不是 pending，结束
修改为 rejected
保存 reason
执行回调
```

## 3. 写 resolvePromise

记住顺序：

```
状态是否 pending
       ↓
是否循环引用
       ↓
x 是否 thenable
   ↙          ↘
 是            否
吸收状态       直接 fulfilled
```

## 4. 写 constructor

```
创建 resolve
创建 reject
try 执行 executor
catch 时 reject
```

## 5. 写 then

四句话：

```
创建新 Promise
保存成功/失败回调
尝试执行回调
返回新 Promise
```

## 6. 写 flush

记住三种结果：

```
没传回调 → 状态穿透
回调正常返回 → resolvePromise(新 Promise, 返回值)
回调抛异常 → rejectPromise(新 Promise, 异常)
```

---

# 十五、你这版还需要注意的两个问题

第一个是循环引用后要 `return`：

```
if (x === promise) {
  return rejectPromise(
    promise,
    new TypeError("Chaining cycle detected for promise #<Promise>"),
  );
}
```

第二个是 thenable 调用需要更加严谨。比如：

```
const thenable = {
  then(resolve, reject) {
    resolve(1);
    reject(2);
  },
};
```

规范实现需要保证 thenable 的 `resolve/reject` 只能第一次有效，并捕获读取或调用 `then` 时出现的异常。

所以更完整的 thenable 解析通常写成：

```
const resolvePromise = (promise, x) => {
  if (promise._state !== PENDING) return;

  if (promise === x) {
    return rejectPromise(
      promise,
      new TypeError("Chaining cycle detected"),
    );
  }

  if (!isObject(x) && !isFunction(x)) {
    promise._state = FULFILLED;
    promise._data = x;
    _flushHandlers(promise);
    return;
  }

  let called = false;

  try {
    const then = x.then;

    if (!isFunction(then)) {
      promise._state = FULFILLED;
      promise._data = x;
      _flushHandlers(promise);
      return;
    }

    queueMicrotask(() => {
      try {
        then.call(
          x,
          (value) => {
            if (called) return;
            called = true;
            resolvePromise(promise, value);
          },
          (reason) => {
            if (called) return;
            called = true;
            rejectPromise(promise, reason);
          },
        );
      } catch (error) {
        if (called) return;
        called = true;
        rejectPromise(promise, error);
      }
    });
  } catch (error) {
    if (called) return;
    called = true;
    rejectPromise(promise, error);
  }
};
```

最后把整套逻辑压缩成一句适合背诵的话：

> 当前 Promise 状态确定后，异步执行 `then` 对应的回调；回调返回普通值，新 Promise 成功；返回 Promise，新 Promise 吸收它的状态；抛出异常，新 Promise 失败；没有回调就进行状态穿透。
