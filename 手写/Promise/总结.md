你最近正在手写 `MyPromise`，可以把 Promise 的全部知识压缩成一句话：

> Promise 是一个表示“未来结果”的状态机，`then` 负责注册回调并返回一个新 Promise，后一个 Promise 的状态由回调返回值决定。

# 1. Promise 的基本作用

Promise 用来处理异步操作，例如：

```js
function getData() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve("请求成功");
    }, 1000);
  });
}

getData().then((data) => {
  console.log(data);
});
```

相比传统回调：

```js
getUser((user) => {
  getOrders(user.id, (orders) => {
    getDetail(orders[0].id, (detail) => {
      console.log(detail);
    });
  });
});
```

Promise 可以写成链式调用：

```js
getUser()
  .then((user) => getOrders(user.id))
  .then((orders) => getDetail(orders[0].id))
  .then((detail) => console.log(detail))
  .catch((error) => console.error(error));
```

---

# 2. Promise 的三个状态

```js
pending    // 等待中
fulfilled  // 已成功
rejected   // 已失败
```

状态只能变化一次：

```text
pending → fulfilled
pending → rejected
```

一旦改变，就不能再次改变。

```js
const promise = new Promise((resolve, reject) => {
  resolve(1);
  reject("失败");
  resolve(2);
});

promise.then(console.log); // 1
```

后面的 `reject()` 和 `resolve(2)` 都不会生效。

---

# 3. Promise 构造函数是同步执行的

```js
console.log(1);

new Promise((resolve) => {
  console.log(2);
  resolve();
});

console.log(3);
```

输出：

```text
1
2
3
```

`new Promise(executor)` 中的 `executor` 会立即同步执行。

但 `then` 回调异步执行：

```js
console.log(1);

Promise.resolve().then(() => {
  console.log(2);
});

console.log(3);
```

输出：

```text
1
3
2
```

---

# 4. Promise 回调属于微任务

```js
console.log(1);

setTimeout(() => {
  console.log(2);
});

Promise.resolve().then(() => {
  console.log(3);
});

console.log(4);
```

输出：

```text
1
4
3
2
```

执行顺序：

```text
同步代码 → 微任务 → 宏任务
```

常见微任务：

```js
Promise.then
Promise.catch
Promise.finally
queueMicrotask
MutationObserver
```

常见宏任务：

```js
setTimeout
setInterval
I/O
用户交互事件
```

---

# 5. `then` 是 Promise 最核心的方法

```js
promise.then(onFulfilled, onRejected);
```

例如：

```js
Promise.resolve("成功").then(
  (value) => {
    console.log(value);
  },
  (error) => {
    console.log(error);
  },
);
```

通常更推荐：

```js
Promise.resolve("成功")
  .then((value) => {
    console.log(value);
  })
  .catch((error) => {
    console.log(error);
  });
```

因为 `catch` 可以捕获整个链条前面产生的异常。

---

# 6. `then` 每次都会返回一个新 Promise

```js
const p1 = Promise.resolve(1);

const p2 = p1.then((value) => {
  return value + 1;
});

console.log(p1 === p2); // false

p2.then(console.log); // 2
```

这是 Promise 能够链式调用的根本原因。

---

# 7. `then` 返回值决定新 Promise 的状态

## 7.1 返回普通值

```js
Promise.resolve(1)
  .then((value) => {
    return value + 1;
  })
  .then(console.log); // 2
```

等价于：

```js
Promise.resolve(1)
  .then((value) => {
    return Promise.resolve(value + 1);
  })
  .then(console.log);
```

新 Promise 成功，值为返回值。

## 7.2 没有返回值

```js
Promise.resolve(1)
  .then((value) => {
    console.log(value);
  })
  .then(console.log); // undefined
```

没有写 `return`，相当于：

```js
return undefined;
```

## 7.3 返回 Promise

```js
Promise.resolve()
  .then(() => {
    return new Promise((resolve) => {
      setTimeout(() => resolve(100), 1000);
    });
  })
  .then(console.log); // 一秒后输出 100
```

后面的 Promise 会等待返回的 Promise。

## 7.4 抛出异常

```js
Promise.resolve()
  .then(() => {
    throw new Error("出错了");
  })
  .catch((error) => {
    console.log(error.message);
  });
```

抛出异常等价于返回一个失败的 Promise：

```js
return Promise.reject(new Error("出错了"));
```

## 7.5 返回 thenable

thenable 是具有 `then` 方法的对象：

```js
const thenable = {
  then(resolve) {
    resolve("thenable 成功");
  },
};

Promise.resolve(thenable).then(console.log);
```

Promise 会“吸收”这个 thenable 的最终状态。

# 8. 值穿透和错误穿透

## 8.1 值穿透

```js
Promise.resolve(10)
  .then()
  .then()
  .then(console.log); // 10
```

本质上相当于：

```js
.then((value) => value);
```

## 8.2 错误穿透

```js
Promise.reject("出错")
  .then()
  .then()
  .catch(console.log); // 出错
```

本质上相当于：

```js
.then(undefined, (error) => {
  throw error;
});
```

所以错误会一直向后传递，直到被 `catch` 捕获。

---

# 9. `catch`

```js
promise.catch(onRejected);
```

等价于：

```js
promise.then(undefined, onRejected);
```

注意，`catch` 如果正常返回，后面的 Promise 会变成成功状态：

```js
Promise.reject("失败")
  .catch((error) => {
    console.log(error);
    return "恢复成功";
  })
  .then(console.log); // 恢复成功
```

如果想让错误继续传递，需要重新抛出：

```js
Promise.reject("失败")
  .catch((error) => {
    console.log(error);
    throw error;
  })
  .catch((error) => {
    console.log("再次捕获：", error);
  });
```

---

# 10. `finally`

无论成功还是失败，`finally` 都会执行：

```js
request()
  .then(handleSuccess)
  .catch(handleError)
  .finally(() => {
    hideLoading();
  });
```

`finally` 不接收结果参数，并且通常不会修改原来的结果：

```js
Promise.resolve(1)
  .finally(() => {
    return 100;
  })
  .then(console.log); // 1
```

失败状态也会保留：

```js
Promise.reject("错误")
  .finally(() => {
    console.log("清理资源");
  })
  .catch(console.log); // 错误
```

但如果 `finally` 抛出异常或返回失败的 Promise，会覆盖原结果：

```js
Promise.resolve(1)
  .finally(() => {
    throw new Error("finally 出错");
  })
  .catch((error) => {
    console.log(error.message);
  });
```

# 11. 常用静态方法

## 11.1 `Promise.resolve`

创建成功 Promise：

```js
Promise.resolve(100).then(console.log);
```

如果传入 Promise，一般直接返回它：

```js
const p1 = Promise.resolve(1);
const p2 = Promise.resolve(p1);

console.log(p1 === p2); // true
```

## 11.2 `Promise.reject`

创建失败 Promise：

```js
Promise.reject(new Error("失败")).catch(console.error);
```

注意：它不会吸收传入 Promise 的状态，而是直接把参数当作失败原因。

## 11.3 `Promise.all`

等待所有 Promise 成功：

```js
Promise.all([
  Promise.resolve(1),
  Promise.resolve(2),
  Promise.resolve(3),
]).then(console.log); // [1, 2, 3]
```

特点：

- 全部成功才成功
    
- 返回结果顺序和传入顺序一致
    
- 一个失败就立即失败
    
- 普通值会被转换成成功 Promise
    

```js
Promise.all([
  new Promise((resolve) => setTimeout(() => resolve("慢"), 1000)),
  Promise.resolve("快"),
]).then(console.log);

// ["慢", "快"]
```

虽然第二个先完成，但结果仍按传入顺序排列。

## 11.4 `Promise.allSettled`

等待所有 Promise 完成，不管成功还是失败：

```js
Promise.allSettled([
  Promise.resolve(1),
  Promise.reject("失败"),
]).then(console.log);
```

结果：

```js
[
  { status: "fulfilled", value: 1 },
  { status: "rejected", reason: "失败" },
];
```

适合批量请求，想收集所有结果的场景。

## 11.5 `Promise.race`

第一个完成的 Promise 决定最终结果：

```js
Promise.race([
  new Promise((resolve) => setTimeout(() => resolve("A"), 1000)),
  new Promise((resolve) => setTimeout(() => resolve("B"), 500)),
]).then(console.log); // B
```

注意是第一个“完成”，不一定是第一个成功。

## 11.6 `Promise.any`

第一个成功的 Promise 决定结果：

```js
Promise.any([
  Promise.reject("A 失败"),
  Promise.resolve("B 成功"),
  Promise.resolve("C 成功"),
]).then(console.log); // B 成功
```

如果全部失败，会得到 `AggregateError`：

```js
Promise.any([
  Promise.reject("A"),
  Promise.reject("B"),
]).catch((error) => {
  console.log(error instanceof AggregateError); // true
  console.log(error.errors); // ["A", "B"]
});
```

## 11.7 四个聚合方法对比

|方法|成功条件|失败条件|是否等待全部|
|---|---|---|---|
|`Promise.all`|全部成功|任意一个失败|失败时不再等待结果|
|`Promise.allSettled`|永远成功|不会失败|是|
|`Promise.race`|第一个完成的是成功|第一个完成的是失败|否|
|`Promise.any`|任意一个成功|全部失败|成功后不再等待结果|

# 12. Promise 和 async/await

`async/await` 本质上是 Promise 的语法糖。

## 12.1 async 函数一定返回 Promise

```js
async function fn() {
  return 100;
}

console.log(fn()); // Promise
fn().then(console.log); // 100
```

抛出异常会返回失败 Promise：

```js
async function fn() {
  throw new Error("失败");
}

fn().catch(console.error);
```

## 12.2 await 等待 Promise

```js
async function fn() {
  const result = await Promise.resolve(100);
  console.log(result);
}
```

可以大致理解为：

```js
Promise.resolve(100).then((result) => {
  console.log(result);
});
```

`await` 后面的代码相当于放进 Promise 微任务中。

## 12.3 捕获错误

```js
async function fn() {
  try {
    const data = await request();
    return data;
  } catch (error) {
    console.error(error);
    throw error;
  }
}
```

# 13. 高频输出题

## 面试题 1

```js
console.log(1);

const promise = new Promise((resolve) => {
  console.log(2);
  resolve();
});

promise.then(() => {
  console.log(3);
});

setTimeout(() => {
  console.log(4);
});

console.log(5);
```

输出：

```text
1
2
5
3
4
```

原因：

```text
同步：1、2、5
微任务：3
宏任务：4
```

## 面试题 2

```js
Promise.resolve()
  .then(() => {
    console.log(1);
    return 2;
  })
  .then(console.log);

console.log(3);
```

输出：

```text
3
1
2
```

## 面试题 3

```js
Promise.resolve()
  .then(() => {
    console.log(1);
    throw new Error("失败");
  })
  .then(() => {
    console.log(2);
  })
  .catch(() => {
    console.log(3);
  })
  .then(() => {
    console.log(4);
  });
```

输出：

```text
1
3
4
```

`throw` 跳过成功回调，进入 `catch`；`catch` 正常执行后，链条恢复为成功状态。

## 面试题 4

```js
const p = Promise.resolve();

p.then(() => console.log(1));
p.then(() => console.log(2));

console.log(3);
```

输出：

```text
3
1
2
```

同一个 Promise 可以注册多个回调，按照注册顺序执行。

# 14. 高频概念面试题

## 1. Promise 解决了什么问题？

主要解决：

- 回调嵌套导致的回调地狱
    
- 错误处理分散
    
- 异步流程难以组合
    
- 异步结果状态不明确
    

但 Promise 只是改善写法，不会自动取消请求，也不会让异步代码变成同步代码。

## 2. Promise 是同步还是异步？

准确回答：

- Promise 构造函数的执行器同步执行
    
- `then/catch/finally` 回调放入微任务队列异步执行
    
- Promise 表示的任务本身是否异步，取决于具体代码
    

## 3. Promise 是并发还是并行？

Promise 本身既不代表并发，也不保证并行。

```js
const p1 = request1();
const p2 = request2();

await Promise.all([p1, p2]);
```

两个请求通常是并发发起的，但 JavaScript 回调仍在主线程执行。并行通常需要 Web Worker、Worker Thread 等。

## 4. `then` 为什么必须返回新 Promise？

如果返回原 Promise：

- 无法根据回调返回值产生新状态
    
- 无法实现连续链式调用
    
- 无法捕获当前回调抛出的异常
    
- 容易出现状态冲突
    

因此每次 `then` 都创建一个独立的新 Promise。

## 5. `then(resolve, reject)` 和 `then(resolve).catch(reject)` 一样吗？

不完全一样。

```js
promise.then(
  () => {
    throw new Error("then 成功回调出错");
  },
  handleError,
);
```

这里的 `handleError` 不能捕获同级成功回调抛出的异常。

而：

```js
promise
  .then(() => {
    throw new Error("then 成功回调出错");
  })
  .catch(handleError);
```

后面的 `catch` 可以捕获。

## 6. Promise 可以取消吗？

原生 Promise 本身不能取消。

但可以取消 Promise 对应的具体任务，例如取消 `fetch`：

```js
const controller = new AbortController();

fetch("/api/data", {
  signal: controller.signal,
});

controller.abort();
```

取消的是网络请求，不是 Promise 对象本身。

## 7. Promise 如何避免链式循环？

```js
const p = Promise.resolve();

const p2 = p.then(() => {
  return p2;
});
```

`p2` 的结果依赖自己，会被拒绝：

```text
TypeError: Chaining cycle detected for promise
```

手写 Promise 时需要判断：

```js
if (promise === x) {
  reject(new TypeError("Chaining cycle detected"));
}
```

# 15. 高频手写题

## 1. 手写 `Promise.all`

```js
function promiseAll(iterable) {
  const items = Array.from(iterable);

  return new Promise((resolve, reject) => {
    if (items.length === 0) {
      resolve([]);
      return;
    }

    const results = new Array(items.length);
    let completed = 0;

    items.forEach((item, index) => {
      Promise.resolve(item).then(
        (value) => {
          results[index] = value;
          completed++;

          if (completed === items.length) {
            resolve(results);
          }
        },
        reject,
      );
    });
  });
}
```

关键点：

- 空数组直接成功
    
- 使用 `Promise.resolve` 兼容普通值和 thenable
    
- 按照原顺序保存结果
    
- 任意一个失败就 reject
    

## 2. 实现超时控制

```js
function withTimeout(promise, delay) {
  const timeout = new Promise((_, reject) => {
    setTimeout(() => {
      reject(new Error("请求超时"));
    }, delay);
  });

  return Promise.race([promise, timeout]);
}
```

更完善的版本还应该清理定时器。

## 3. 实现延迟函数

```js
function sleep(delay) {
  return new Promise((resolve) => {
    setTimeout(resolve, delay);
  });
}

await sleep(1000);
console.log("一秒后执行");
```

## 4. 实现请求重试

```js
async function retry(fn, times) {
  let lastError;

  for (let i = 0; i < times; i++) {
    try {
      return await fn();
    } catch (error) {
      lastError = error;
    }
  }

  throw lastError;
}
```

使用：

```js
retry(() => fetch("/api/data"), 3);
```

## 5. 串行执行 Promise 任务

```js
async function runSerial(tasks) {
  const results = [];

  for (const task of tasks) {
    results.push(await task());
  }

  return results;
}
```

注意任务必须写成函数：

```js
const tasks = [
  () => request1(),
  () => request2(),
  () => request3(),
];
```

如果直接传 Promise，它们在进入函数前就已经开始执行了。

# 16. 常见错误写法

## 1. 忘记 return

错误：

```js
getUser()
  .then((user) => {
    getOrders(user.id);
  })
  .then((orders) => {
    console.log(orders); // undefined
  });
```

正确：

```js
getUser()
  .then((user) => {
    return getOrders(user.id);
  })
  .then((orders) => {
    console.log(orders);
  });
```

箭头函数可以简写：

```js
getUser()
  .then((user) => getOrders(user.id))
  .then(console.log);
```

## 2. 使用 `forEach` 搭配 async

错误：

```js
items.forEach(async (item) => {
  await save(item);
});

console.log("完成"); // 不会等待
```

串行：

```js
for (const item of items) {
  await save(item);
}
```

并发：

```js
await Promise.all(items.map((item) => save(item)));
```

## 3. `new Promise(async () => {})`

不推荐：

```js
new Promise(async (resolve, reject) => {
  const data = await request();
  resolve(data);
});
```

直接写：

```js
async function getData() {
  return await request();
}
```

或者：

```js
function getData() {
  return request();
}
```

Promise 的 executor 设计为同步函数，使用 async executor 容易产生难以捕获的错误。

## 4. 把函数执行结果传给 `then`

错误：

```js
promise.then(handleSuccess());
```

这会立即执行 `handleSuccess`。

正确：

```js
promise.then(handleSuccess);
```

或者：

```js
promise.then(() => handleSuccess());
```

# 17. 手写 MyPromise 必须掌握的核心

你目前手写 Promise 时，重点就是下面这些：

```text
1. pending、fulfilled、rejected 三种状态
2. 状态只能改变一次
3. executor 立即同步执行
4. 捕获 executor 抛出的异常
5. pending 时保存多个回调
6. then 返回一个新 Promise
7. then 回调通过微任务执行
8. 普通返回值让新 Promise 成功
9. 抛出异常让新 Promise 失败
10. 返回 Promise/thenable 时吸收其状态
11. 防止循环引用
12. thenable 只能成功或失败一次
13. catch 等价于 then(undefined, onRejected)
14. finally 保留原来的状态和值
```

其中最难、也是面试最重要的是：

```js
resolvePromise(promise, x);
```

它解决的问题是：

> `then` 回调返回的 `x`，到底应该让新 Promise 成功、失败，还是继续等待另一个 Promise？

这部分就是 Promise Resolution Procedure，也是手写 Promise 的灵魂。

# 18. 建议你的掌握顺序

按照前端面试的重要性：

```text
状态变化
→ executor 与 then 的执行时机
→ 微任务和事件循环
→ then 返回新 Promise
→ 返回值与错误传递
→ catch 和 finally
→ all/allSettled/race/any
→ async/await
→ 输出题
→ 手写 Promise.all
→ 手写 MyPromise
→ 并发控制、重试、超时
```

面试中最核心的回答不是“Promise 有三个状态”，而是：

> `then` 每次返回一个新 Promise，新 Promise 的状态由回调的返回值决定；返回普通值就成功，返回 Promise 就吸收其状态，抛出异常就失败。`then` 回调通过微任务执行。
