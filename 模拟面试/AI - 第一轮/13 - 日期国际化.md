下一题针对你简历中的“北京时间日期边界”：

假设每日缺勤检查任务在北京时间每天 00:05 执行，但 Vercel 函数运行在 UTC 时区。请说明：

- 你会如何确定“今天”的北京时间日期；
- MongoDB 中考勤日期如何存储和查询；
- 如何避免 `new Date("2026-07-28")`、服务器时区和夏令时导致查询错位；
- 如果任务重复执行，如何保证不会重复创建缺勤记录？

我会把“业务日期”和“时间点”分开处理。北京时间每天 00:05 执行缺勤检查时，实际检查的应该是前一天的业务日期，因为当天才刚开始。

首先，任务不会直接使用服务器的 `new Date().getDate()`，而是统一以 `Asia/Shanghai` 为业务时区。例如通过 `Intl.DateTimeFormat` 或时区库，将当前 UTC 时间转换成北京时间，得到类似：

```text
2026-07-29 00:05 Asia/Shanghai
```

然后把目标业务日期确定为：

```text
2026-07-28
```

任务调度本身也可以配置为：

```text
TZ=Asia/Shanghai 5 0 * * *
```

但我不会只依赖调度器的时区配置，任务内部仍然会根据明确的业务时区计算日期。对于重试任务，还可以直接把 `businessDate` 放进任务事件中，避免任务延迟执行后检查错日期。

考勤记录中，我会增加一个明确的业务日期字段：

```ts
{
  employeeId,
  businessDate: "2026-07-28",
  checkIn: Date,
  checkOut: Date,
  status: "PRESENT" | "ABSENT" | "LATE"
}
```

其中：

- `businessDate` 是员工所属业务日，使用 `YYYY-MM-DD` 字符串；
- `checkIn`、`checkOut` 是真实时间点，使用 MongoDB BSON Date 存储，内部统一按 UTC 保存；
- `businessDate` 不依赖服务器时区，也不会因为展示时区变化而改变。

如果需要按时间范围查询，我会把北京时间某天的开始和下一天的开始转换成 UTC：

```text
北京时间 2026-07-28 00:00
→ UTC 2026-07-27 16:00

北京时间 2026-07-29 00:00
→ UTC 2026-07-28 16:00
```

MongoDB 查询使用左闭右开区间：

```ts
{
  checkIn: {
    $gte: startUtc,
    $lt: endUtc,
  },
}
```

我不会直接写：

```ts
new Date("2026-07-28")
```

因为日期字符串没有明确时区，容易被解释为 UTC 零点，再在本地时区显示成其他日期。也不会使用：

```ts
new Date(year, month, day)
```

因为它依赖服务器本地时区。正确做法是使用 `Asia/Shanghai` 进行显式转换，例如通过 `Temporal`、Luxon 或 `date-fns-tz` 从北京时间的本地日期生成 UTC 时间点。

另外，结束时间不能简单地认为是开始时间加 24 小时。更稳妥的方式是分别计算“当天北京时间零点”和“下一天北京时间零点”。虽然 `Asia/Shanghai` 目前没有夏令时，但使用 IANA 时区规则可以避免未来切换时区或复用代码到其他地区时出现问题。

为了防止任务重复执行，我会建立唯一索引：

```ts
attendanceSchema.index(
  { employeeId: 1, businessDate: 1 },
  { unique: true },
);
```

缺勤任务为每个在职员工执行幂等写入：

```ts
await Attendance.updateOne(
  {
    employeeId,
    businessDate,
  },
  {
    $setOnInsert: {
      employeeId,
      businessDate,
      status: "ABSENT",
    },
  },
  { upsert: true },
);
```

如果员工已经有正常考勤记录，`$setOnInsert` 不会覆盖它；如果已经存在缺勤记录，重复执行也不会新增记录。即使两个任务实例同时执行，唯一索引也能阻止重复数据，遇到重复键错误时将其视为已经处理即可。

因此核心设计是：

```text
北京时间计算业务日期
→ businessDate 明确保存日期归属
→ checkIn/checkOut 使用 UTC 时间点
→ 查询使用北京时间边界转换后的 UTC 区间
→ employeeId + businessDate 唯一索引
→ $setOnInsert + upsert 保证任务幂等
```

这样即使 Vercel 运行在 UTC、任务发生重试，或者同一个任务被重复触发，也不会出现日期错位和重复创建缺勤记录的问题。
