回答得不错，架构划分和鉴权链路比较清晰。继续追问一个关键问题：

你提到文档正文通过 Liveblocks Room 实时同步，而 Convex 主要保存元数据。那么请问：

1. 用户刷新页面或离开房间后，Tiptap 的正文内容如何持久化？
2. 如果多人同时编辑，最终内容如何保证不会丢失或覆盖？
3. 你实现多格式导出时，导出的正文数据从哪里获取？

请结合具体的数据流说明。

这个问题很关键。这里需要区分“实时同步”和“业务数据库持久化”。

第一，用户刷新页面或离开房间后，正文内容并不是保存在 Convex 中，而是由 Liveblocks Room 持久化。创建文档时，Convex 中的 `initialContent` 主要用于保存模板或初始内容。用户进入页面后，Next.js 服务端先从 Convex 获取文档元数据和初始内容，然后使用文档 ID 加入对应的 Liveblocks Room。Tiptap 通过 `useLiveblocksExtension` 连接这个 Room。如果 Room 中已经存在协同编辑内容，就加载 Room 中的最新内容；只有 Room 为空时，才使用 Convex 传入的 `initialContent` 作为初始值。因此用户刷新或重新进入同一个文档时，会重新加入同一个 Room，并恢复之前的正文内容。

第二，多人同时编辑时，我没有自己实现基于时间戳的覆盖逻辑，而是使用 Liveblocks Tiptap 扩展底层的 Yjs 协同机制。每个用户的编辑会被转换成协同操作，通过 CRDT 合并到共享文档中，而不是简单地采用最后一次请求覆盖前一次请求。因此两个人同时输入、删除或者修改不同位置的内容时，系统可以合并操作，尽量避免内容丢失。项目中还关闭了 Tiptap 默认的历史记录，因为 Liveblocks 扩展提供了协同场景下的撤销和重做处理。另外我开启了实验性的离线支持，用于网络短暂中断时暂存本地操作，恢复连接后再同步。

整体数据流可以概括为：

用户操作 Tiptap 编辑器，编辑器生成协同操作；Liveblocks 将操作广播给同一 Room 的其他用户，并持久化共享文档；其他客户端接收到操作后更新各自的 Tiptap 实例。Convex 在这里主要负责文档标题、所有者、组织关系和访问权限，而不是每次输入都保存正文。

第三，多格式导出目前是在客户端完成的，正文数据直接从当前 Tiptap Editor 实例获取。工具栏通过 Zustand 拿到当前的 `editor` 实例：

- JSON 导出使用 `editor.getJSON()`；
- HTML 导出使用 `editor.getHTML()`；
- 纯文本导出使用 `editor.getText()`；
- PDF 导出则调用浏览器的 `window.print()`，利用当前已经渲染好的编辑器 DOM 打印。

所以导出时不需要再次从 Convex 查询正文，因为当前编辑器已经包含了 Liveblocks 同步后的最新内容。这样也能保证用户导出的内容是当前页面正在看到的版本。需要说明的是，目前项目的正文最终持久化依赖 Liveblocks；如果以后要实现自己的数据备份、版本历史或跨服务迁移，我会增加一个服务端同步或定时快照机制，将 Liveblocks 中的编辑器 JSON 定期保存到 Convex 或对象存储中。
