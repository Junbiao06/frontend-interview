下一题：

文档列表支持关键词搜索。用户连续输入时，你不希望每输入一个字符就发起一次请求，同时还要避免旧请求晚返回后覆盖新搜索结果。

请你设计一个 React 搜索方案，说明：

- 如何实现 debounce；
- 如何清理定时器；
- 如何处理组件卸载；
- 如何避免请求结果乱序导致旧数据覆盖新数据。

我会把方案分成“输入防抖”和“请求竞态控制”两部分。

用户输入先保存到本地状态，使用 `useEffect` 配合定时器实现 debounce。例如等待 300～500 毫秒，如果用户继续输入，就清除上一次定时器并重新计时。

```
function useDocumentSearch(keyword: string) {
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(false);
  const requestId = useRef(0);

  useEffect(() => {
    const controller = new AbortController();
    const currentRequestId = ++requestId.current;
    const query = keyword.trim();

    const timer = window.setTimeout(async () => {
      if (!query) {
        setData([]);
        setLoading(false);
        return;
      }

      setLoading(true);

      try {
        const response = await api.get("/documents", {
          params: { keyword: query },
          signal: controller.signal,
        });

        // 只接受当前请求的结果
        if (
          !controller.signal.aborted &&
          currentRequestId === requestId.current
        ) {
          setData(response.data);
        }
      } catch (error) {
        if (
          controller.signal.aborted ||
          currentRequestId !== requestId.current
        ) {
          return;
        }

        // 处理真正的请求错误
      } finally {
        if (
          !controller.signal.aborted &&
          currentRequestId === requestId.current
        ) {
          setLoading(false);
        }
      }
    }, 300);

    return () => {
      // 用户继续输入时清除旧定时器
      window.clearTimeout(timer);

      // 取消尚未完成的旧请求
      controller.abort();
    };
  }, [keyword]);

  return { data, loading };
}
```

当关键词变化时，`useEffect` 的清理函数会先执行，清除上一次的定时器并中止上一次请求。只有用户停止输入超过 300 毫秒后，才会真正发起请求。

为了避免旧请求晚返回覆盖新结果，我同时使用了两层保护：

第一层是 `AbortController`，尽可能取消不再需要的网络请求；第二层是 `requestId`。每次发起新的搜索都会递增 ID，响应返回时只有当它仍然等于当前 ID，才允许更新状态。因为请求取消和响应返回之间可能存在竞态，所以不能只依赖 `abort()`。

组件卸载时，`useEffect` 的清理函数同样会清除定时器并取消请求，避免卸载后继续更新状态。空关键词则直接清空结果，不发送请求。

如果项目中已经有通用的 `useDebounce` Hook，也可以先得到 `debouncedKeyword`，再对它发请求；但无论采用哪种 debounce 方式，请求层仍然需要 `AbortController` 和请求序列号来处理乱序响应。
