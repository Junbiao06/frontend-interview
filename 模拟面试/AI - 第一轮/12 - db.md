这个搜索方案比较完整：防抖解决请求频率，`AbortController` 和 `requestId` 共同解决请求竞态，清理逻辑也覆盖了卸载场景。

下一题考察后端数据一致性：

员工请假审批通过时，需要同时完成：

1. 将请假单状态从 `PENDING` 修改为 `APPROVED`；
2. 扣减员工剩余年假；
3. 发送审批通过邮件。

如果管理员重复点击审批按钮，或者两个管理员同时审批同一张请假单，你如何保证年假不会被重复扣减？哪些操作应该放进 MongoDB 事务，邮件发送又应该如何处理？


我会把审批逻辑放在后端 Service 层，由 MongoDB 事务保证“状态变更”和“年假扣减”要么同时成功，要么同时回滚。

审批接口先经过 `protect` 和 `protectAdmin`，确认是管理员后，再调用类似 `approveLeave(leaveId, adminId)` 的服务方法。

事务中主要做三件事：

```ts
await session.withTransaction(async () => {
  const leave = await LeaveApplication.findOneAndUpdate(
    {
      _id: leaveId,
      status: "PENDING",
    },
    {
      $set: {
        status: "APPROVED",
        approvedBy: adminId,
        approvedAt: new Date(),
      },
    },
    { new: true, session },
  );

  if (!leave) {
    throw new AppError(409, "Leave already processed");
  }

  if (leave.type === "ANNUAL") {
    const days = calculateLeaveDays(leave.startDate, leave.endDate);

    const employee = await Employee.findOneAndUpdate(
      {
        _id: leave.employeeId,
        annualLeaveBalance: { $gte: days },
      },
      {
        $inc: { annualLeaveBalance: -days },
      },
      { new: true, session },
    );

    if (!employee) {
      throw new AppError(409, "Insufficient annual leave balance");
    }
  }

  await OutboxEvent.create(
    [
      {
        type: "LEAVE_APPROVED",
        aggregateId: leave._id,
        employeeId: leave.employeeId,
        status: "PENDING",
      },
    ],
    { session },
  );
});
```

这里最关键的是 `status: "PENDING"` 这个条件更新。两个管理员同时审批时，只有一个事务能够把状态从 `PENDING` 改成 `APPROVED`，另一个请求会匹配不到记录，直接返回 409，不会扣减年假。

即使同一个管理员重复点击，也会因为状态已经不是 `PENDING` 而失败。对于同一个员工的多个请假申请，年假扣减还使用：

```ts
annualLeaveBalance: { $gte: days }
```

配合 `$inc`，可以避免并发审批导致余额变成负数。所有读取和写入都必须使用同一个 MongoDB session，否则就不能真正保证事务一致性。

邮件发送不应该直接放在 MongoDB 事务内部。因为邮件服务是外部系统，无法和 MongoDB 共享事务。如果数据库已经提交但邮件发送失败，不能回滚请假审批；反过来，如果邮件先发出但数据库事务最终回滚，员工会收到错误通知。

因此我会采用 Outbox Pattern：在同一个 MongoDB 事务中写入一条 `LEAVE_APPROVED` 事件，事务提交成功后，再由后台任务或 Inngest 读取 Outbox，调用 Resend 发送邮件。邮件发送失败时记录重试次数和下次重试时间，使用指数退避进行重试。

Outbox 表需要对 `eventType + aggregateId` 建唯一索引，保证同一张请假单只生成一条审批通知事件。邮件消费者也要支持幂等处理，避免任务重试导致重复发送。

所以最终保证的是：

```text
请假状态 + 年假扣减 + Outbox 事件：MongoDB 事务内原子提交
邮件发送：事务提交后异步执行，失败可重试
重复审批：条件更新和唯一事件约束保证幂等
```

业务数据可以做到一次性提交，邮件这类外部副作用通常采用“事务消息 + 至少一次投递 + 幂等消费”的方式处理。
