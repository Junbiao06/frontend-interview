# Shard Upload Lab

一个 React + Vite + Express 大文件分片上传示例，包含：

- 浏览器 `Blob.slice` 切片，不一次性读取完整文件
- 抽样 SHA-256 文件指纹
- 分片并发上传与失败重试
- 暂停、继续与断点续传
- 已完成文件秒传
- Express 服务端分片校验、流式合并与下载

## 抽样哈希是什么

哈希函数可以把任意长度的数据映射为固定长度的结果。相同输入必然得到相同输出，而输入只要有变化，结果通常也会明显变化。因此，哈希常被当作文件的“指纹”。

本项目没有读取整个大文件，而是采用更快的抽样策略：

1. 第一个分片：完整读取。
2. 中间的每一个分片：读取开头 2 字节、正中间 2 字节、末尾 2 字节。
3. 最后一个分片：完整读取。
4. 把这些样本按原文件顺序拼接，再计算 SHA-256。

假如文件被切成 `A、B、C、D` 四片，参与哈希的数据是：

```text
A 全部
+ B[头 2B] + B[中 2B] + B[尾 2B]
+ C[头 2B] + C[中 2B] + C[尾 2B]
+ D 全部
→ SHA-256
```

这种结果更准确地说是“抽样指纹”，优点是快、内存占用稳定，适合在上传前识别文件并做秒传/续传查询。它的代价是存在抽样未覆盖区域被修改、指纹却不变的可能，所以不能用来替代安全校验或严格完整性验证。生产环境可在服务端合并后再对完整文件计算一次全量 SHA-256。

## 本地运行

```bash
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，Express API 运行在 `http://localhost:3001`。

生产方式：

```bash
npm run build
npm start
```

此时 Express 会同时托管构建后的前端与上传接口。

## 接口

- `POST /api/upload/check`：检查文件是否已完成、返回已有分片编号。
- `POST /api/upload/chunk`：以 `application/octet-stream` 上传单个分片。
- `POST /api/upload/merge`：校验并按编号合并所有分片。
- `GET /api/files/:key`：下载合并后的文件。

上传文件默认保存在 `server/storage`，该目录已加入 `.gitignore`。
