# 一、先抓住最核心的关系

JavaScript 中几乎所有对象都有一个内部属性：

```
[[Prototype]]
```

它指向另一个对象。访问某个属性时，如果当前对象找不到，JavaScript 就会沿着 `[[Prototype]]` 不断向上查找，这条路径就是“原型链”。

我们平时接触到的几个名字分别是：

|名称|含义|
|---|---|
|`prototype`|构造函数上的属性，指向“将来实例的原型对象”|
|`__proto__`|对象访问自身 `[[Prototype]]` 的历史写法|
|`constructor`|通常存在于原型对象上，指回创建它的构造函数|
|`[[Prototype]]`|JavaScript 引擎内部真正使用的原型引用|

最重要的关系是：

```
实例.__proto__ === 构造函数.prototype
构造函数.prototype.constructor === 构造函数
```

例如：

```
function Person(name) {
  this.name = name;
}

const p = new Person("张三");

console.log(p.__proto__ === Person.prototype); // true
console.log(Person.prototype.constructor === Person); // true
console.log(p.constructor === Person); // true
```

关系图：

```
p
│
│ [[Prototype]] / __proto__
▼
Person.prototype
│
│ [[Prototype]] / __proto__
▼
Object.prototype
│
▼
null
```

# 二、原型链解决了什么问题

假设我们直接把方法写在构造函数里：

```
function Person(name) {
  this.name = name;

  this.sayHello = function () {
    console.log(`你好，我是${this.name}`);
  };
}

const p1 = new Person("张三");
const p2 = new Person("李四");

console.log(p1.sayHello === p2.sayHello); // false
```

每次执行 `new Person()`，都会重新创建一个 `sayHello` 函数，浪费内存。

可以把公共方法放在 `Person.prototype` 上：

```
function Person(name) {
  this.name = name;
}

Person.prototype.sayHello = function () {
  console.log(`你好，我是${this.name}`);
};

const p1 = new Person("张三");
const p2 = new Person("李四");

console.log(p1.sayHello === p2.sayHello); // true

p1.sayHello(); // 你好，我是张三
p2.sayHello(); // 你好，我是李四
```

这里：

- `name` 是每个实例自己的属性
- `sayHello` 是所有实例共享的方法
- `p1` 找不到 `sayHello`，就去 `Person.prototype` 上找

```
console.log(p1.hasOwnProperty("name"));     // true
console.log(p1.hasOwnProperty("sayHello")); // false

console.log("sayHello" in p1); // true
```

区别是：

- `hasOwnProperty()`：只判断对象自身
- `in`：对象自身和原型链都检查

# 三、属性查找过程

来看一个更清楚的例子：

```
const grandParent = {
  house: "祖宅"
};

const parent = Object.create(grandParent);
parent.car = "汽车";

const child = Object.create(parent);
child.phone = "手机";

console.log(child.phone); // 手机
console.log(child.car);   // 汽车
console.log(child.house); // 祖宅
console.log(child.money); // undefined
```

查找 `child.house` 的过程：

```
1. child 自身有没有 house？没有
2. parent 有没有 house？没有
3. grandParent 有没有 house？有
4. 返回 "祖宅"
```

如果一直找到 `null` 都没有，就返回 `undefined`。

```
console.log(Object.getPrototypeOf(child) === parent); // true
console.log(Object.getPrototypeOf(parent) === grandParent); // true
console.log(Object.getPrototypeOf(grandParent) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null
```

# 四、`prototype` 属性

## 1. `prototype` 属于构造函数

普通函数通常都有一个 `prototype` 属性：

```
function Person() {}

console.log(Person.prototype);
// { constructor: Person }
```

它的作用主要是：当函数通过 `new` 调用时，成为新实例的原型。

```
function Person() {}

const p = new Person();

console.log(Object.getPrototypeOf(p) === Person.prototype); // true
```

注意，不是所有函数都有可用的 `prototype`。

例如箭头函数没有：

```
const fn = () => {};

console.log(fn.prototype); // undefined

// const obj = new fn();
// TypeError: fn is not a constructor
```

普通函数既能直接调用，也可以作为构造函数：

```
function Fn() {}

console.log(Fn.prototype); // 存在
new Fn();                  // 可以
```

类也有 `prototype`：

```
class Person {
  sayHello() {
    console.log("hello");
  }
}

console.log(typeof Person.prototype); // object
console.log(Person.prototype.sayHello); // function
```

---

## 2. `prototype` 本身也是对象

```
function Person() {}

console.log(typeof Person.prototype); // object
console.log(Person.prototype.__proto__ === Object.prototype); // true
```

所以它自己也有原型链：

```
Person.prototype
        ↓
Object.prototype
        ↓
null
```

我们给 `Person.prototype` 添加的方法，本质就是给一个普通对象添加属性：

```
function Person() {}

Person.prototype.say = function () {
  console.log("说话");
};

Person.prototype.age = 18;

const p = new Person();

p.say();           // 说话
console.log(p.age); // 18
```

# 五、`__proto__` 属性

`__proto__` 是访问对象内部 `[[Prototype]]` 的历史写法：

```
const obj = {};
console.log(obj.__proto__ === Object.prototype); // true
```

推荐使用标准方法：

```
Object.getPrototypeOf(obj);
Object.setPrototypeOf(obj, anotherObject);
```

例如：

```
const animal = {
  eat() {
    console.log("吃东西");
  }
};

const dog = {
  bark() {
    console.log("汪汪");
  }
};

Object.setPrototypeOf(dog, animal);

dog.bark(); // 汪汪
dog.eat();  // 吃东西

console.log(Object.getPrototypeOf(dog) === animal); // true
```

虽然下面也能工作：

```
dog.__proto__ = animal;
```

但不推荐，因为：

- `__proto__` 是历史兼容接口
- 修改现有对象的原型可能影响性能
- `Object.getPrototypeOf()`、`Object.create()` 更明确

创建对象时可以直接指定原型：

```
const animal = {
  eat() {
    console.log("吃东西");
  }
};

const dog = Object.create(animal);

dog.name = "旺财";
dog.eat(); // 吃东西
```

# 六、`constructor` 属性

默认情况下，一个函数的 `prototype` 对象上有一个 `constructor` 属性，指向函数本身。

```
function Person() {}

console.log(Person.prototype.constructor === Person); // true
```

实例为什么也能访问 `constructor`？

```
const p = new Person();

console.log(p.constructor === Person); // true
console.log(p.hasOwnProperty("constructor")); // false
```

因为查找过程是：

```
p 自身没有 constructor
        ↓
Person.prototype 上有 constructor
        ↓
得到 Person
```

因此，严格来说不是：

```
p.constructor
```

一定直接存储在 `p` 上，而是通过原型链继承来的。

---

## 替换 `prototype` 的坑

如果直接替换整个 `prototype`：

```
function Person() {}

Person.prototype = {
  sayHello() {
    console.log("hello");
  }
};

const p = new Person();

console.log(p.constructor === Person); // false
console.log(p.constructor === Object); // true
```

原因是新对象：

```
{
  sayHello() {}
}
```

它没有自己的 `constructor`，于是沿原型链找到：

```
Object.prototype.constructor === Object
```

可以手动补回：

```
function Person() {}

Person.prototype = {
  constructor: Person,

  sayHello() {
    console.log("hello");
  }
};

const p = new Person();

console.log(p.constructor === Person); // true
```

不过这样创建的 `constructor` 默认是可枚举的，与原生默认状态不完全一样。更严谨的写法是：

```
Object.defineProperty(Person.prototype, "constructor", {
  value: Person,
  writable: true,
  configurable: true,
  enumerable: false
});
```

更简单的做法是不要替换整个 `prototype`，直接添加属性：

```
function Person() {}

Person.prototype.sayHello = function () {
  console.log("hello");
};
```

这样原来的 `constructor` 不会丢失。

# 七、`new` 到底做了什么

下面这段代码：

```
function Person(name) {
  this.name = name;
}

Person.prototype.sayHello = function () {
  console.log(this.name);
};

const p = new Person("张三");
```

可以近似理解为：

```
function myNew(Constructor, ...args) {
  // 1. 创建一个新对象
  // 2. 让新对象的原型指向 Constructor.prototype
  const obj = Object.create(Constructor.prototype);

  // 3. 调用构造函数，让 this 指向新对象
  const result = Constructor.apply(obj, args);

  // 4. 构造函数主动返回对象时，使用该对象
  if (
    result !== null &&
    (typeof result === "object" || typeof result === "function")
  ) {
    return result;
  }

  // 否则返回刚创建的对象
  return obj;
}

const p = myNew(Person, "张三");

console.log(p.name); // 张三
console.log(Object.getPrototypeOf(p) === Person.prototype); // true
```

所以：

```
实例.__proto__ === 构造函数.prototype
```

是 `new` 操作建立起来的。

---

## 构造函数主动返回对象

```
function Person() {
  this.name = "张三";

  return {
    name: "李四"
  };
}

const p = new Person();

console.log(p.name); // 李四
console.log(p instanceof Person); // false
```

如果构造函数返回普通值，则普通值会被忽略：

```
function Person() {
  this.name = "张三";
  return 100;
}

const p = new Person();

console.log(p.name); // 张三
console.log(p instanceof Person); // true
```

# 八、实例属性会遮蔽原型属性

```
function Person() {}

Person.prototype.name = "原型中的名字";

const p = new Person();

console.log(p.name); // 原型中的名字

p.name = "实例自己的名字";

console.log(p.name); // 实例自己的名字
console.log(Person.prototype.name); // 原型中的名字
```

执行：

```
p.name = "实例自己的名字";
```

通常不是修改原型上的属性，而是在 `p` 自身创建同名属性。

```
console.log(p.hasOwnProperty("name")); // true
```

删除实例属性后，原型属性又会“出现”：

```
delete p.name;

console.log(p.name); // 原型中的名字
console.log(p.hasOwnProperty("name")); // false
```

这叫属性遮蔽。

# 九、引用类型属性的共享问题

如果把数组放到原型上，所有实例会共享同一个数组：

```
function Person() {}

Person.prototype.hobbies = [];

const p1 = new Person();
const p2 = new Person();

p1.hobbies.push("篮球");

console.log(p1.hobbies); // ["篮球"]
console.log(p2.hobbies); // ["篮球"]
console.log(p1.hobbies === p2.hobbies); // true
```

这是因为两个实例拿到的是同一个原型数组。

因此：

- 方法适合放在原型上共享
- 每个实例独立的数据，尤其数组和对象，适合放在构造函数里

```
function Person() {
  this.hobbies = [];
}

Person.prototype.addHobby = function (hobby) {
  this.hobbies.push(hobby);
};

const p1 = new Person();
const p2 = new Person();

p1.addHobby("篮球");

console.log(p1.hobbies); // ["篮球"]
console.log(p2.hobbies); // []
```

# 十、内置对象的原型链

## 数组

```
const arr = [1, 2, 3];

console.log(arr.__proto__ === Array.prototype); // true
console.log(Array.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__); // null
```

完整链条：

```
arr
 ↓
Array.prototype
 ↓
Object.prototype
 ↓
null
```

所以数组既能使用数组方法，也能使用对象方法：

```
arr.push(4);                  // 来自 Array.prototype
arr.hasOwnProperty("length"); // 来自 Object.prototype
```

---

## 日期对象

```
const date = new Date();

console.log(Object.getPrototypeOf(date) === Date.prototype); // true
console.log(Object.getPrototypeOf(Date.prototype) === Object.prototype); // true
```

---

## 函数对象

函数本身也是对象：

```
function Person() {}

console.log(Person.__proto__ === Function.prototype); // true
console.log(Function.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__); // null
```

注意这里有两条不同的链。

实例的链：

```
new Person()
      ↓
Person.prototype
      ↓
Object.prototype
      ↓
null
```

构造函数 `Person` 自己的链：

```
Person
  ↓
Function.prototype
  ↓
Object.prototype
  ↓
null
```

因此下面两个概念完全不同：

```
Person.prototype
Person.__proto__
```

- `Person.prototype`：将来 `Person` 实例的原型
- `Person.__proto__`：函数对象 `Person` 自己的原型

```
function Person() {}

console.log(Person.prototype === Person.__proto__); // false
console.log(Person.__proto__ === Function.prototype); // true

const p = new Person();

console.log(p.__proto__ === Person.prototype); // true
```

# 十一、几个容易混淆的经典关系

```
function Person() {}

const p = new Person();
```

判断结果：

```
p.__proto__ === Person.prototype
// true
```

```
Person.prototype.constructor === Person
// true
```

```
p.constructor === Person
// true，通过原型链找到
```

```
Person.__proto__ === Function.prototype
// true，因为 Person 本身是函数对象
```

```
Person.prototype.__proto__ === Object.prototype
// true，因为 Person.prototype 是普通对象
```

```
Function.prototype.__proto__ === Object.prototype
// true
```

```
Object.prototype.__proto__ === null
// true
```

非常特殊但经典的关系：

```
Function.__proto__ === Function.prototype
// true
```

```
Object.__proto__ === Function.prototype
// true
```

因为：

- `Function` 本身也是函数
- `Object` 本身也是函数
- 函数对象的原型通常是 `Function.prototype`

# 十二、`instanceof` 如何工作

```
p instanceof Person
```

不是检查 `p.constructor === Person`，而是检查：

> `Person.prototype` 是否出现在 `p` 的原型链上。

```
function Person() {}

const p = new Person();

console.log(p instanceof Person); // true
console.log(p instanceof Object); // true
```

原因：

```
p
 ↓
Person.prototype      找到 Person.prototype
 ↓
Object.prototype      找到 Object.prototype
 ↓
null
```

可以近似实现：

```
function myInstanceof(instance, Constructor) {
  let proto = Object.getPrototypeOf(instance);
  const target = Constructor.prototype;

  while (proto !== null) {
    if (proto === target) {
      return true;
    }

    proto = Object.getPrototypeOf(proto);
  }

  return false;
}

console.log(myInstanceof(p, Person)); // true
console.log(myInstanceof(p, Object)); // true
```

---

## 为什么不能完全相信 `constructor`

`constructor` 可以被随意修改：

```
function Person() {}

const p = new Person();

Person.prototype.constructor = Array;

console.log(p.constructor === Array); // true
console.log(p instanceof Person); // true
console.log(p instanceof Array); // false
```

所以判断实例类型时，`instanceof` 通常比 `constructor` 更符合原型链语义。

跨 iframe 等特殊环境下，`instanceof` 也可能失效。判断内置类型常使用：

```
Object.prototype.toString.call([]);
// "[object Array]"

Object.prototype.toString.call(new Date());
// "[object Date]"
```

# 十三、使用原型链实现继承

## ES5 写法

```
function Animal(name) {
  this.name = name;
}

Animal.prototype.eat = function () {
  console.log(`${this.name}正在吃东西`);
};

function Dog(name, color) {
  Animal.call(this, name);
  this.color = color;
}

// 让 Dog.prototype 继承 Animal.prototype
Dog.prototype = Object.create(Animal.prototype);

// 恢复 constructor
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function () {
  console.log(`${this.name}正在汪汪叫`);
};

const dog = new Dog("旺财", "黄色");

dog.eat();  // 旺财正在吃东西
dog.bark(); // 旺财正在汪汪叫

console.log(dog instanceof Dog);    // true
console.log(dog instanceof Animal); // true
console.log(dog instanceof Object); // true
```

原型链：

```
dog
 ↓
Dog.prototype
 ↓
Animal.prototype
 ↓
Object.prototype
 ↓
null
```

其中：

```
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true

console.log(
  Object.getPrototypeOf(Dog.prototype) === Animal.prototype
); // true
```

---

## ES6 `class` 写法

```
class Animal {
  constructor(name) {
    this.name = name;
  }

  eat() {
    console.log(`${this.name}正在吃东西`);
  }
}

class Dog extends Animal {
  constructor(name, color) {
    super(name);
    this.color = color;
  }

  bark() {
    console.log(`${this.name}正在汪汪叫`);
  }
}

const dog = new Dog("旺财", "黄色");

dog.eat();
dog.bark();

console.log(dog instanceof Dog);    // true
console.log(dog instanceof Animal); // true
```

`class` 并没有放弃原型链，它主要是原型继承的更现代语法。

```
console.log(
  Object.getPrototypeOf(Dog.prototype) === Animal.prototype
); // true
```

静态继承还有另一条链：

```
console.log(Object.getPrototypeOf(Dog) === Animal); // true
```

因此 `extends` 同时建立了两条关系：

```
实例方法继承：

Dog.prototype
      ↓
Animal.prototype


静态属性和静态方法继承：

Dog
 ↓
Animal
```

例如：

```
class Animal {
  static category = "动物";

  static introduce() {
    console.log("这是动物类");
  }
}

class Dog extends Animal {}

console.log(Dog.category); // 动物
Dog.introduce();           // 这是动物类
```

# 十四、`Object.create(null)` 的特殊对象

普通对象的原型最终指向 `Object.prototype`：

```
const obj = {};

console.log(Object.getPrototypeOf(obj) === Object.prototype); // true
```

但可以创建一个完全没有原型的对象：

```
const dictionary = Object.create(null);

console.log(Object.getPrototypeOf(dictionary)); // null
console.log(dictionary.toString); // undefined
console.log(dictionary.hasOwnProperty); // undefined
```

这种对象没有任何原型链上的方法，适合用作纯字典。

检查自身属性时可以使用：

```
dictionary.name = "张三";

console.log(Object.hasOwn(dictionary, "name")); // true
```

现代代码推荐：

```
Object.hasOwn(obj, "property")
```

而不是：

```
obj.hasOwnProperty("property")
```

因为后者可能被覆盖，或者对象根本没有原型。

# 十五、一道综合题

```
function Person(name) {
  this.name = name;
}

Person.prototype.name = "原型名字";

Person.prototype.say = function () {
  console.log(this.name);
};

const p1 = new Person("张三");
const p2 = new Person("李四");

p1.say();
p2.say();
```

结果：

```
张三
李四
```

因为执行 `p1.say()` 时：

1. `p1` 自身没有 `say`
2. 在 `Person.prototype` 找到 `say`
3. 但调用形式是 `p1.say()`
4. 所以方法内部的 `this` 是 `p1`
5. `this.name` 优先找到 `p1` 自身的 `"张三"`

继续：

```
delete p1.name;

p1.say(); // 原型名字
```

删除自身的 `name` 后：

1. `this` 仍然是 `p1`
2. `p1` 自身没有 `name`
3. 沿原型链找到 `Person.prototype.name`
4. 输出 `"原型名字"`

# 十六、最终总结

记住下面四句话：

```
实例.__proto__ === 构造函数.prototype
```

```
构造函数.prototype.constructor === 构造函数
```

```
构造函数.__proto__ === Function.prototype
```

```
Object.prototype.__proto__ === null
```

再分别理解三个属性：

- `prototype`：函数用于安排“未来实例原型”的对象。
- `__proto__`：当前对象访问自身原型的历史接口，推荐使用 `Object.getPrototypeOf()`。
- `constructor`：原型对象上默认指回构造函数的普通属性，可以被修改，因此不能绝对依赖。
- 原型链：属性查找时，从对象自身开始，沿 `[[Prototype]]` 一层层向上，直到 `null`。
